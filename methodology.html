Research Methodology

A systematic experimental approach for developing, implementing and evaluating the proposed CyberShield AI cybersecurity framework.

1. Research Design

This research follows an experimental and prototype-based development approach. A selected cybersecurity dataset will be used to train and evaluate a machine learning model. The resulting detection output will then be used to investigate cloud-based event management and security notification mechanisms.

2. Dataset Selection

The experiment will use a publicly available cybersecurity dataset containing examples of normal and malicious activity.

  • CICIDS2017: Network traffic data containing benign activity and multiple attack categories.
  • UNSW-NB15: Network traffic dataset designed for intrusion detection research.
  • NSL-KDD: An established dataset used in network intrusion detection experiments.

The final experiment will select a suitable dataset based on availability, relevance, licensing and research objectives. These datasets are alternatives, not a claim that all three have already been tested.

3. Data Preparation

Before model training, the selected dataset will undergo preparation to improve consistency and suitability for analysis.

  • Remove duplicate or irrelevant records where appropriate.
  • Handle missing and inconsistent values.
  • Convert categorical fields into numerical representations.
  • Normalize or scale numerical features when required by the algorithm.
  • Separate input features from target labels.

4. Algorithm Selection

Suitable classification algorithms will be considered for identifying patterns in the prepared dataset.

Random Forest

An ensemble learning method that combines multiple decision trees to produce a classification result.

Decision Tree

A tree-based algorithm that makes predictions through a sequence of feature-based decisions.

Support Vector Machine

A supervised learning algorithm that identifies decision boundaries between different data classes.

The final model will be selected after considering experimental performance, dataset characteristics and computational requirements.

5. Model Training and Validation

The prepared dataset will be divided into training and testing subsets. The training subset will be used to fit the model, while the testing subset will evaluate its performance on previously unseen records.

  • Use a reproducible train-test split.
  • Apply stratified sampling where appropriate.
  • Use cross-validation when suitable.
  • Monitor overfitting and class imbalance.
  • Record model settings and experimental results.

6. Performance Evaluation

Model performance will be evaluated using established classification metrics.

Accuracy

Measures the proportion of correctly classified records.

(TP + TN) / (TP + TN + FP + FN)

Precision

Measures how many predicted positive records are actually positive.

TP / (TP + FP)

Recall

Measures how many actual positive records are correctly identified.

TP / (TP + FN)

F1-Score

Combines precision and recall using their harmonic mean.

2 × (Precision × Recall) / (Precision + Recall)

TP = True Positive, TN = True Negative, FP = False Positive, FN = False Negative.

7. Experimental Environment

The proposed experiment will use a Python-based development environment for dataset preparation, model training and result analysis. AWS services will be configured separately for the cloud integration prototype.

  • Python and suitable machine learning libraries.
  • Jupyter Notebook or an equivalent development environment.
  • A selected intrusion detection dataset.
  • AWS test environment with controlled permissions.
  • Sample security events for notification testing.

8. Integration Testing

After individual components are developed, controlled tests will examine whether detection results can be passed to the event management component and whether configured events can trigger the intended notification workflow.

  • Test normal and suspicious sample records.
  • Verify event classification output.
  • Check cloud access permissions.
  • Test notification delivery using AWS SNS.
  • Verify event records and response logs.

9. Result Analysis

Experimental results will be documented using tables, classification reports and confusion matrices. The analysis will examine model performance, false alarms, missed detections and integration test outcomes.

10. Reproducibility and Ethical Considerations

Experiments will use authorized datasets and controlled test environments. Dataset sources, preprocessing steps, model parameters and evaluation procedures will be documented to support reproducibility.

Testing will not involve unauthorized access to third-party systems. Cloud credentials and sensitive configuration information will be protected.
