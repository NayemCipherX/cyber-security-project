System Workflow

A step-by-step explanation of how CyberShield AI is designed to process security events, identify potential threats and initiate appropriate responses.

01

Security Event Generation

The process begins when security-related activity occurs in a monitored environment. Events may include unusual login attempts, unexpected network requests or suspicious activity from a test dataset.

02

Event Collection

Relevant event information is collected from configured sources. Each record may contain timestamps, source information, event types and other useful attributes.

03

Data Preprocessing

Collected records are checked, cleaned and converted into a suitable format. Missing values, inconsistent fields and irrelevant information are handled before model analysis.

04

Feature Extraction

Relevant characteristics are selected from the prepared data. These features help the machine learning model examine patterns associated with normal or suspicious activities.

05

AI-Based Threat Classification

The trained model analyzes the selected features and produces a classification result. Depending on the model and dataset, an event may be classified as normal or potentially malicious.

06

Risk Assessment

The system evaluates the classification result using predefined rules. The purpose is to determine the event's priority and whether further investigation or an alert is required.

07

Notification and Response

If an event meets the configured alert conditions, the proposed notification component can publish a message through AWS SNS. Any prevention action must follow authorized and controlled security rules.

08

Logging and Reporting

Event details, classification results and response records are intended to be stored for later investigation. Reports can help evaluate detection performance and identify recurring security patterns.

Example: Suspicious Login Attempts

Imagine a test environment receives several unusual login attempts within a short period. The event records are collected and prepared for analysis. The trained model evaluates their characteristics and identifies a potentially suspicious pattern. If the event satisfies the configured alert rules, the system can generate a security notification and record the incident for investigation.

Research implementation note: This workflow describes the proposed system. Live event collection, model execution and AWS notification integration will be implemented and tested during backend development.
